# 《巡梦》前端页面风格设计

## 1. 设计结论

采用“安静沉浸型”中的“低光安全舱”方向：界面像夜里醒来时可进入的一间低光梦舱，温柔、安全、私密。它服务的是一个产品界面，不是官网，也不是概念展示。用户需要快速输入梦境、接收 Agent 整理、保存并回看，所以视觉必须沉浸但稳定。

## 2. 设计定位

- 默认 register：product。
- 情绪底色：温柔安全。
- 主视觉气质：低亮度、柔和层次、梦境氛围。
- 信息优先级：故事与输入第一，关键词与背景第二，装饰永远最后。
- 动效策略：沉浸动效优先，但只用于氛围层和反馈，不干扰阅读与输入。

## 3. 页面风格

### 3.1 启动页

启动页应非常安静，只保留产品名、梦者名输入和进入按钮。背景可以有极慢的雾化呼吸，但不要出现营销式价值主张、功能卡片或夸张 hero。文案应像“进入自己的梦境空间”，不要像“提升梦境管理效率”。

### 3.2 梦境拼合舱

拼合舱是核心页面。布局建议：

- 顶部轻量状态栏：当前梦者、日历、保存、切换梦者。
- 中央故事区：最大视觉稳定性，宽度适合长文阅读。
- 氛围层：关键词气泡围绕故事慢漂浮，不遮挡文本。
- 底部输入区：固定、可靠、清楚，包含文本输入、语音、发送。
- 碎片匣：侧边或底部抽屉，收纳原始片段。

拼合舱不应像聊天应用，也不应像仪表盘。它的交互核心是“把片段逐步拼成一个梦”。

### 3.3 日历页

日历页需要比拼合舱更清晰克制。日期、梦境数量、当日列表和进入详情要容易扫描。可以用小光点表达有梦境的日期，但不能牺牲可读性。空状态应安静提示，而不是鼓励式营销文案。

### 3.4 梦境详情页

详情页可以比拼合舱更沉浸。背景根据主情绪轻微变化，故事、碎片、关键词和陪伴式回应形成分层阅读。它应像回到一个梦里，而不是查看一份报告。

## 4. 视觉系统

### 4.1 色彩

色彩使用低光中性加少量暖色锚点。避免纯黑、纯白和高饱和霓虹。实现时优先使用 OKLCH，保持深色区域的可读性。

建议方向：

- 背景：深蓝灰、暖紫灰、低亮墨色。
- 主文字：带暖色倾向的雾白，不用纯白。
- 主行动：低饱和暖金或烛光色，少量使用。
- 情绪标签：低饱和玫影、蓝雾、灰绿等，避免彩虹化。

### 4.2 字体

产品 UI 以清晰 sans 为主体。梦境标题可以略带文学气质，但不应影响界面一致性。若引入衬线字体，只用于启动页标题或详情页梦境标题，不能用于按钮、标签和表单。

### 4.3 容器与层次

容器使用 8px 左右轻圆角。避免嵌套卡片和厚重阴影。深度主要通过色调层次、细边界和背景雾化表达。底部输入区、碎片匣和浮动关键词可以有轻微抬升感。

### 4.4 图标

使用统一图标库，优先 lucide。图标只用于明确操作：保存、日历、语音、发送、返回、切换梦者。不要使用星盘、水晶、塔罗、眼睛等玄学符号作为装饰。

## 5. 动效原则

动效采用“沉浸动效优先”，但必须符合产品任务。

- 关键词气泡：慢漂浮、轻微呼吸，避免随机高速移动。
- 背景：极低频率亮度或雾化变化。
- Agent loading：用柔和状态表现“正在拼合”，不要大转圈占据故事区。
- 保存成功：短暂暖光反馈。
- 页面转场：150-250ms，淡入或轻微位移。
- 减少动效：遵守 `prefers-reduced-motion`，保留必要状态反馈。

## 6. 明确避开的方向

- AI SaaS：大渐变、发光 CTA、营销卡片、指标英雄区。
- 心理咨询：医疗白绿、诊断语气、过度疗愈插画。
- 玄学占卜：星盘、水晶、符号阵、塔罗视觉。
- AI 生成感：一眼可见的紫蓝渐变、玻璃卡片、漂浮光球堆叠。
- 过度装饰：气泡、背景、动效不能遮挡或稀释故事阅读。

## 7. 可用性约束

- 主故事文本对比度必须达到 WCAG AA。
- 输入区永远可见或容易返回。
- 保存、发送、语音识别都必须有 loading、成功、失败状态。
- 移动端不允许气泡遮挡输入框。
- 用户无法使用语音时，文字输入流程不受影响。
- 键盘焦点必须可见。

## 8. 后续实现建议

实现时先建立设计 token：颜色、字体、半径、间距、动效时长。再实现基础组件：Button、InputBar、KeywordBubble、DreamStoryPanel、FragmentDrawer、CalendarDay、DreamListItem。最后组合页面，避免一开始把所有视觉和业务写进单个页面文件。
