# 《巡梦》Demo 产品需求文档（PRD）

## 1. 文档信息

| 字段 | 内容 |
| --- | --- |
| 产品名称 | 巡梦 |
| 文档版本 | V1.1 |
| 文档状态 | Demo/MVP 评审后修订版 |

## 2. 项目概述

《巡梦》是一个围绕“做梦后快速记录、拼合与回看”的 Web 应用 Demo。它帮助用户在梦境刚醒来、记忆仍然碎片化时，通过文字或浏览器语音转文字输入梦境片段，并由大模型 Agent 将片段整理为更完整的梦境故事，识别其中的情绪、关键词与意象，再用沉浸式界面承接用户情绪。

本项目不是普通梦境记事本，而是一个“梦境拼合与情绪承接空间”。产品语气应保持温柔、克制、陪伴式，不做玄学断言、不做心理诊断、不强行解释用户潜意识。

## 3. 产品目标

### 3.1 业务目标

- 在 Demo 场景中完整展示“输入梦境片段 -> Agent 拼合 -> 保存 -> 日历回看 -> 用户隔离”的核心闭环。
- 验证真实大模型 API、SQLite 持久化、Web Speech API 在本地演示环境中的可用性。
- 形成一个可继续扩展为个人梦境档案、情绪趋势与意象图谱的产品雏形。

### 3.2 用户目标

- 用户可以在记忆模糊时快速记录梦境碎片，而不被复杂表单打断。
- 用户可以通过 Agent 的温柔追问继续回忆，而不是被冷冰冰地分析。
- 用户可以按日期回看历史梦境，并看到故事、情绪、关键词和原始片段。
- 用户可以用不同梦者名演示数据隔离，避免互相看到梦境记录。

### 3.3 非目标

- 不提供医疗、心理诊断或治疗建议。
- 不做正式账号体系、密码登录、云同步和多端同步。
- 不做第三方语音识别 API 接入。
- Demo 阶段不支持梦境编辑、删除、导出和多人协作。

## 4. 目标用户

| 用户类型 | 用户画像 | 核心诉求 |
| --- | --- | --- |
| 梦境记录者 | 想记录梦境，但醒来后只能记得碎片的人 | 快速输入、不打断回忆、稍后可回看 |
| 自我观察者 | 对梦境、情绪和意象有兴趣的人 | 看到温和整理后的故事、情绪与关键词 |
| Demo 体验者 | 评审、展示或开发测试人员 | 快速理解产品闭环，并验证数据隔离与持久化 |

## 5. 核心体验

用户打开应用后输入“梦者名”，进入“梦境拼合舱”。用户可以持续输入梦境片段，也可以使用浏览器语音转文字快速补充。每次提交后，Agent 读取当前 DreamState 和新增片段，重新整理故事、识别情绪和关键词，并生成一句温柔追问。

页面中央显示 Agent 整理出的梦境故事，周围漂浮关键词气泡，包含情绪、人物、地点、物品、颜色、动作等。原始输入片段不常驻主视觉区域，而是收纳在可折叠的“碎片匣”中。用户保存梦境后，可在日历视图中按日期查看历史梦境，并进入沉浸式详情页回看。

## 7. 用户流程

### 7.1 启动与梦者区分

1. 用户打开应用。
2. 页面要求输入“梦者名”。
3. 前端调用 `POST /api/dreamers` 创建或获取对应 dreamer。
4. 当前 dreamer 信息保存到浏览器 `localStorage`。
5. 后续所有梦境读写均绑定 `dreamerId`。
6. 用户可以切换梦者，用于演示不同用户之间的数据隔离。

### 7.2 碎片化输入

1. 用户进入梦境拼合舱。
2. 用户通过底部输入框输入梦境片段。
3. 用户也可以点击语音按钮，使用浏览器语音转文字填充输入框。
4. 用户点击发送。
5. 前端将当前 `DreamState` 与新增 `fragment` 发送到 `POST /api/dream-agent`。
6. 后端调用大模型。
7. 后端校验并返回结构化 `DreamState`。
8. 页面更新故事、关键词气泡、情绪状态和引导问题。

### 7.3 Agent 引导

每次用户发送片段后，Agent 必须给出一个陪伴式追问。

追问要求：

- 每次只问一个问题。
- 问题必须来自用户已经输入的梦境细节。
- 语气温柔、陪伴，不像问卷。
- 不强行解释梦境。
- 不做心理疾病诊断。
- 不使用“这说明你……”这类定性表达。

示例：

```text
这种“不舍”听起来比追逐本身更靠近梦的中心。你还记得追你的人像谁，或者像什么吗？
```

### 7.4 保存梦境

用户点击保存后，系统将当前整理后的梦境状态写入 SQLite。

保存内容包括：

- 原始碎片列表
- Agent 整理出的完整故事
- 标题
- 主情绪
- 情绪强度
- 情绪曲线
- 关键词
- 意象
- 陪伴式回应
- 最后一次引导问题
- 氛围配置
- 日期与时间
- 所属 dreamer

保存约束：

- 未产生有效故事时不可保存，并提示用户先输入梦境片段。
- 连续点击保存不得产生重复记录。
- 保存成功后应给出明确反馈。
- 保存失败时保留当前页面状态，允许重试。

### 7.5 日历回看

1. 用户进入日历页面。
2. 系统查询当前 dreamer 的梦境。
3. 有梦境的日期用光点、颜色或标记展示。
4. 用户点击日期后展示当天梦境列表。
5. 用户点击梦境进入详情页。

### 7.6 沉浸式详情

详情页根据梦境状态渲染：

- 完整梦境故事
- 原始碎片折叠区
- 情绪与关键词气泡
- 情绪承接文本
- 基于主情绪的背景氛围
- 返回日历或梦境拼合舱的入口

## 8. 页面需求

### 8.1 启动页

功能：

- 输入梦者名。
- 创建或读取 dreamer。
- 如果浏览器已有最近 dreamer，可提供快速继续入口。
- 支持切换梦者。

交互与状态：

- 梦者名为空时禁止进入。
- 梦者名去除首尾空格后长度需为 1-24 个字符。
- 网络或服务端异常时展示可理解错误，并允许重试。

页面气质：

- 简洁、安静。
- 文案贴合“进入自己的梦境空间”。

### 8.2 梦境拼合舱

布局：

- 中央：Agent 整理出的梦境故事。
- 周围：漂浮关键词气泡。
- 底部：用户输入框、语音按钮、发送按钮。
- 角落：碎片匣折叠按钮。
- 顶部：当前梦者、进入日历、保存梦境、切换梦者。

交互：

- 用户可多次发送碎片。
- 每次发送后展示 loading 状态，并禁用重复发送。
- Agent 返回后更新故事和气泡。
- 新关键词气泡淡入并轻微漂浮。
- 气泡不可遮挡主要故事文本。
- 输入框内容在发送成功后清空；发送失败时保留。

### 8.3 碎片匣

功能：

- 折叠展示用户原始输入片段。
- 展示每个片段的输入方式：文字或语音转文字。
- 展示输入时间。
- Demo 阶段仅查看，不要求编辑。

### 8.4 日历页

功能：

- 月历视图。
- 按日期展示当前梦者的梦境数量。
- 点击日期查看当天梦境。
- 点击梦境进入详情。

边界：

- 无梦境日期不可进入空详情。
- 当前 dreamer 无梦境时展示空状态。
- 查询必须携带 `dreamerId`，禁止跨梦者展示。

### 8.5 梦境详情页

功能：

- 展示保存后的 DreamState。
- 根据情绪渲染沉浸式背景。
- 展示关键词气泡。
- 展示完整故事与情绪承接文本。
- 支持返回日历或梦境拼合舱。

## 9. Agent 需求

### 9.1 Agent 定位

Agent 名称：巡梦员。

角色定义：

```text
你不是解梦师，而是帮助用户把梦境碎片温柔拼回来的巡梦员。
```

Agent 不做：

- 玄学断言。
- 心理疾病诊断。
- 生硬问卷。
- 强行解释用户潜意识。
- 输出吓人、定性或指责式内容。

Agent 要做：

- 整理梦境碎片。
- 拼合梦境故事。
- 分析情绪。
- 提取意象与关键词。
- 生成陪伴式回应。
- 给出自然的下一步追问。

### 9.2 Agent 输入

每次请求包含：

- 当前 `DreamState`，可为空。
- 新增用户 `fragment`。
- 当前 `dreamerName`。
- 当前日期时间。

### 9.3 Agent 输出

大模型必须返回 JSON。后端必须校验 JSON 结构，不允许直接信任模型输出。

```json
{
  "title": "蓝黑色的桥",
  "story": "你站在一座很长的桥上，天空是蓝黑色的...",
  "primaryEmotion": "不舍",
  "emotionIntensity": 0.74,
  "emotionArc": ["迷茫", "紧张", "不舍"],
  "keywords": [
    { "text": "桥", "type": "symbol", "weight": 0.9 },
    { "text": "蓝黑色", "type": "color", "weight": 0.7 },
    { "text": "追逐", "type": "action", "weight": 0.8 },
    { "text": "不舍", "type": "emotion", "weight": 1 }
  ],
  "symbols": ["桥", "追逐者", "蓝黑色天空"],
  "gentleReflection": "这个梦里有追逐，但它真正明亮的地方似乎不是恐惧...",
  "followUpQuestion": "你还记得追你的人像谁，或者像什么吗？",
  "atmosphere": {
    "palette": "deep-blue-gold",
    "motion": "slow-floating",
    "density": 0.65
  }
}
```

### 9.4 输出校验规则

- `title`、`story`、`followUpQuestion` 不能为空。
- `emotionIntensity` 必须在 0-1 之间。
- `keywords` 最多返回 12 个，`weight` 必须在 0-1 之间。
- `keyword.type` 允许值：`emotion`、`person`、`place`、`object`、`color`、`action`、`symbol`、`other`。
- 如果模型返回无效 JSON，后端应返回明确错误，不覆盖当前 DreamState。
- 如果模型输出包含诊断、恐吓或强解释，应触发安全降级文案。

## 10. 数据需求

### 10.1 SQLite 表设计

#### dreamers

```sql
CREATE TABLE IF NOT EXISTS dreamers (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL,
  last_seen_at TEXT NOT NULL
);
```

#### dreams

```sql
CREATE TABLE IF NOT EXISTS dreams (
  id TEXT PRIMARY KEY,
  dreamer_id TEXT NOT NULL,
  title TEXT NOT NULL,
  dream_date TEXT NOT NULL,
  story TEXT NOT NULL,
  primary_emotion TEXT,
  emotion_intensity REAL,
  emotion_arc TEXT,
  keywords TEXT,
  symbols TEXT,
  fragments TEXT,
  gentle_reflection TEXT,
  follow_up_question TEXT,
  atmosphere TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (dreamer_id) REFERENCES dreamers(id)
);
```

### 10.2 数据隔离

- 所有 dreams 查询必须携带 `dreamer_id`。
- 用户启动时通过 `dreamerName` 获取 `dreamer_id`。
- 同名 dreamer 视为同一用户。
- 不同用户名称之间梦境不可见。
- 详情接口必须同时校验 `dreamId` 与 `dreamerId`。

### 10.3 持久化

- 梦境保存到 SQLite，刷新后仍然存在。
- 重启服务后数据仍然存在。
- 数据库文件建议存放在 `data/chasing-dream.sqlite`。

## 11. API 需求

### 11.1 创建或获取梦者

```text
POST /api/dreamers
```

请求：

```json
{
  "name": "小林"
}
```

返回：

```json
{
  "id": "dreamer_uuid",
  "name": "小林"
}
```

异常：

- `400`：名称为空或超长。
- `500`：数据库异常。

### 11.2 调用梦境 Agent

```text
POST /api/dream-agent
```

请求：

```json
{
  "dreamerName": "小林",
  "currentState": {},
  "fragment": {
    "content": "我站在一座很长的桥上，天是蓝黑色的。",
    "inputType": "text"
  }
}
```

返回：

```json
{
  "state": {}
}
```

异常：

- `400`：片段为空或输入类型非法。
- `502`：大模型不可用、超时或返回无效结构。
- `500`：服务端异常。

### 11.3 保存梦境

```text
POST /api/dreams
```

请求必须包含 `dreamerId` 与完整 `DreamState`。

要求：

- 后端必须校验 dreamer 是否存在。
- 后端必须校验 `story`、`title`、`dream_date`。
- 保存接口应具备防重复提交机制，可基于前端禁用按钮和后端幂等键实现。

### 11.4 获取当前梦者梦境

```text
GET /api/dreams?dreamerId=xxx
```

要求：

- 仅返回当前 dreamer 的梦境摘要。
- 默认按 `dream_date` 倒序。

### 11.5 获取梦境详情

```text
GET /api/dreams/:id?dreamerId=xxx
```

要求：

- 必须同时匹配 `id` 与 `dreamerId`。
- 找不到或不属于当前 dreamer 时返回 `404`。

## 12. 语音输入需求

使用 Browser Web Speech API。

要求：

- 点击语音按钮开始识别。
- 再次点击或识别结束后停止。
- 识别结果填入底部输入框。
- 用户确认后发送给 Agent。
- 语音转文字仅作为额外录入方式，不绕过用户确认。

边界：

- 浏览器不支持 Web Speech API 时隐藏或禁用语音按钮，并提示改用文字输入。
- 麦克风权限被拒绝时展示友好提示。
- 识别失败时不清空输入框。
- 推荐使用 Chrome 或 Edge 演示。

## 13. 大模型配置

服务端环境变量：

```env
OPENAI_API_KEY=xxx
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4.1-mini
```

要求：

- API Key 只能在服务端使用。
- 前端不得直接调用大模型 API。
- 后端需要校验大模型返回 JSON。
- 如果返回格式异常，应给出可理解的错误提示。
- Demo 要求调用真实大模型，不做固定 mock。

## 14. 非功能需求

### 14.1 性能

- 本地运行稳定。
- Agent 请求期间必须有明确 loading 状态。
- 普通页面加载目标小于 3 秒。
- 非 Agent API 本地响应目标小于 500ms。
- 气泡动画应轻柔，不影响阅读。

### 14.2 安全

- 不应出现 API Key 泄露。
- 不应出现用户 A 查看用户 B 梦境的情况。
- 输入内容必须进行长度限制和基础清洗。
- 前端渲染用户输入和模型输出时必须避免 XSS。
- 服务端日志不得记录完整 API Key。

### 14.3 兼容

- 桌面端优先，移动端和桌面端均可基本使用。
- 推荐浏览器：Chrome、Edge。
- Web Speech API 不可用时不影响文字输入主流程。

### 14.4 可用性

- 页面刷新后当前 dreamer 可从 `localStorage` 恢复。
- 重要操作需有成功、失败、加载状态。
- 错误提示应说明发生了什么，以及用户可以怎么继续。

## 15. 异常与边界场景

| 场景 | 预期处理 |
| --- | --- |
| 梦者名为空 | 禁止进入，提示输入梦者名 |
| 梦者名重复 | 返回已有 dreamer |
| 片段为空 | 禁止发送，提示先输入内容 |
| 用户重复点击发送 | 前端禁用按钮，后端避免重复处理 |
| 大模型超时 | 保留输入，提示稍后重试 |
| 大模型返回无效 JSON | 不覆盖当前状态，提示整理失败 |
| 保存时断网或数据库异常 | 保留当前状态，允许重试 |
| 日历无梦境 | 展示空状态，不跳转详情 |
| 请求他人梦境详情 | 返回 404 |
| 浏览器不支持语音 | 允许文字输入，语音按钮禁用 |

## 16. 演示脚本

1. 打开应用，输入梦者名“小林”。
2. 进入梦境拼合舱。
3. 输入第一段碎片：“我站在一座很长的桥上，天是蓝黑色的。”
4. 展示 Agent 生成故事雏形、关键词气泡和追问。
5. 使用语音输入补充：“好像有人在追我，但我不是很害怕，我有点舍不得。”
6. 展示 Agent 重新整理后的故事，情绪变为“不舍/紧张”。
7. 打开碎片匣，展示原始输入片段。
8. 保存梦境。
9. 进入日历，点击今天。
10. 进入梦境详情，展示沉浸式回看。
11. 切换梦者名“小周”，展示无法看到“小林”的梦境。
12. 切回“小林”，展示历史梦境仍然存在。

## 17. MVP 验收标准

- 用户可以输入梦者名进入应用。
- 同名 dreamer 可被复用，不同 dreamer 数据隔离。
- 用户可以多次输入梦境碎片。
- 用户可以使用浏览器语音转文字作为输入方式。
- 每次发送片段后真实调用大模型 API。
- Agent 能返回完整故事、情绪、关键词和追问。
- 页面中央展示整理后的故事。
- 关键词以漂浮气泡形式展示，且不遮挡主文本。
- 原始片段保存在折叠碎片匣中。
- 用户可以保存梦境。
- 梦境持久化到 SQLite。
- 用户刷新或重启服务后，使用同一梦者名仍可查看梦境。
- 日历页面可以按日期查看梦境。
- 可以从日历进入梦境详情。
- 大模型异常、保存失败、语音不可用时均有可理解提示。
- 前端不暴露 API Key。

## 18. 质量审视结论

### 18.1 技术风险

1. 大模型 JSON 不稳定可能导致页面状态被污染。建议后端增加 schema 校验，失败时不覆盖当前状态。
2. 保存梦境存在重复点击风险。建议保存按钮 loading 期间禁用，并在后端增加幂等键或重复内容保护。
3. dreamerId 是数据隔离关键字段。所有列表和详情查询都必须带 `dreamerId` 并在 SQL 条件中强制匹配。
4. Web Speech API 浏览器支持不一致。语音必须是增强能力，文字输入必须始终可用。
5. 关键词气泡动画可能遮挡阅读。需要给主故事区域预留不可遮挡范围。

### 18.2 用户体验问题

1. 原 PRD 对错误状态描述不足。已补充 loading、失败重试、空状态和语音不可用状态。
2. 保存前置条件不清晰。已明确无有效故事不可保存。
3. Agent 语气边界需要更明确。已补充“不做诊断、不强解释、不定性”的输出边界。
4. 日历空状态和无梦境日期行为需明确。已补充不可进入空详情。

### 18.3 运营与后续需求

1. Demo 阶段应保留清晰演示脚本，方便稳定展示核心闭环。
2. 后续可扩展情绪趋势、意象图谱、导出梦境卡片、云同步等能力。
3. 当前不建议过早引入账号体系，以免增加 Demo 复杂度。

### 18.4 测试要点

1. 同一 dreamer 重复进入应读取同一数据。
2. 不同 dreamer 之间应完全看不到彼此梦境。
3. 片段为空、模型失败、保存失败均不能破坏当前页面状态。
4. 语音权限拒绝和浏览器不支持时，文字输入流程仍可完成。
5. 刷新页面和重启服务后，历史梦境仍可通过日历回看。
6. 关键词气泡在移动端和桌面端都不能遮挡主故事文本。

## 19. 后续可扩展方向

- 梦境情绪趋势统计。
- 梦境意象图谱。
- 多梦境之间的主题关联。
- 流式 Agent 输出。
- 梦境音景或环境声。
- 导出梦境卡片。
- 登录系统与云同步。
- Turso/libSQL 线上 SQLite 部署。
